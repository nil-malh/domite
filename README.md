## Why "domite"

Domite is the pale volcanic rock that forms the Puy de Dôme, the volcano that overlooks Clermont-Ferrand, where Michelin (and ns4kafka) comes from. Sofka is named after a cat; domite is named after the hill above ns4kafka's hometown.

It also suits the job: the Puy de Dôme is a dome, a single view over everything below it, which is what this TUI gives you over your Kafka namespaces. And the name is short and easy to type (`domite`, `:ctx`, `:topics`).

> [!WARNING]
> **AI-Generated Project Disclaimer**
>
> `domite` has been **primarily generated by AI** (from an architectural specification adapting [sofka](https://github.com/nklmilojevic/sofka) to [ns4kafka](https://github.com/michelin/ns4kafka)'s REST contracts). As a sandbox project to learn some ``ratatui-rs`` Please keep in mind what this implies before using it on live environments:
> - **Use at your own risk:** While the codebase is covered by automated tests and server-side `?dryrun=true` validation, subtle edge cases, unhandled API responses, or unexpected behaviors may still exist.
> - **Keep production guardrails on:** Contexts matching `prod*` / `*-prod` default to `readonly = true`, and you can force read-only mode at any time with `domite --readonly` or `:readonly`.
> - **Always inspect dry-run diffs before confirming writes:** Destructive or mutating actions (`delete`, `edit`, `delete-records`, consumer-group offset `reset`, connector state changes) show a preview before execution — review it carefully, and prefer `kafkactl` for critical production changes if in doubt.

## Highlights

- **Zero-setup `kafkactl` drop-in:** Reads your existing `~/.kafkactl/config.yml` contexts and reuses `~/.kafkactl/jwt` tokens (or logs in via `POST /login` and caches tokens with `0600` permissions). Trusts system & corporate root CAs out of the box.
- **One generic object pipeline:** Built around `GET /api-resources` discovery (`Topic`, `Connector`, `ConsumerGroup`, `Schema`, `AccessControlEntry`, `KafkaStream`, `ConnectCluster`, `ResourceQuota`, `RoleBinding`, `Namespace`), with curated columns per kind, JSON-Pointer custom views, and a `NAME / AGE` fallback for any future kind.
- **Background Schema Registry hydration:** Lists thousands of schema subjects instantaneously and hydrates `VERSION`, `ID`, `COMPATIBILITY`, and `TYPE` in the background (prioritizing rows near your cursor). Press `Enter` for a pretty-printed Avro/JSON/Protobuf schema definition, or `y` for the full ns4kafka YAML resource.
- **Explain unhealthy resources (`X`):** Inspect why a `Topic` is in `Fail` phase or view full Java stack traces (`status.tasks[].trace`) for failed `Connector` tasks without leaving the terminal.
- **Safe writes with server dry-run diffs:** Every mutating action (`e` edit in `$EDITOR`, `Ctrl-d` delete, `i` import, `delete-records`, consumer-group offset `reset`) runs against ns4kafka's `?dryrun=true` endpoint first and shows a unified diff or dry-run preview before confirmation.
- **Production guardrails:** Any context named `prod*` / `*-prod` defaults to `readonly = true`. Switch to write mode explicitly with `:write` or `--write`.
- **17 built-in color skins:** Catppuccin (`mocha`, `latte`, `frappe`, `macchiato`), Gruvbox, Nord, Dracula, Solarized, Tokyo Night, One Dark, Rosé Pine, Monokai, and Flexoki — with automatic dark/light terminal detection.

## Installation & Quick Start

### Build from source

```bash
cargo install --path .
```

### Usage

```bash
# Launch using your current context and namespace from ~/.kafkactl/config.yml
domite

# Start directly on a specific resource kind, context, or namespace
domite connectors -c oom-cqt -n coomgbl0
domite schemas
domite cg

# Launch with the built-in in-memory demo cluster (no server needed)
domite --demo

# Headless modes for CI smoke checks and terminal snapshots
domite --check
domite --snapshot

# Generate shell completions (bash, zsh, fish, elvish, powershell)
domite --completions zsh > _domite
```

## Structured `/` Filter Language

Press **`/`** in any table view to filter rows live:

| Syntax | Meaning | Example |
|---|---|---|
| `text` | Case-insensitive substring match across name & cells | `orders dlq` |
| `a\|b` | Match either alternative | `orders\|payments` |
| `"exact text"` | Substring match preserving spaces | `"awaiting processing"` |
| `~needle` | Fuzzy subsequence match | `~opv` (matches `orders.payments.v1`) |
| `/regex/` | Case-insensitive regular expression | `/^coomgbl0\..*_Dlq$/` |
| `!term` | Inverse match (negation) | `!Success` or `!/.*-key$/` |
| `label:pat` | Match against `metadata.labels` or topic `spec.tags` | `label:PCI` |
| `col=val` / `col!=val` | Case-insensitive column equality | `status=Fail` or `state=FAILED` |
| `col>N` / `col>=N` | Numeric column comparison | `partitions>=12` or `lag>0` |
| `age<duration` | Elapsed age comparison (`s`, `m`, `h`, `d`, `w`) | `age<2h` or `age>=7d` |
| `&&`, `\|\|`, `(...)` | Boolean combinations | `(status=Fail \|\| status=Pending) && partitions>=3` |

| `?` | Open help overlay |
| `q` / `Ctrl-c` | Close active overlay or quit `domite` |

### Kind-Specific Actions (`t` Menu)

- **Topic:** Jump to Consumer Groups / ACLs / Schemas, inspect `/spec/configs`, delete records (truncate with dry-run preview), import unsynchronized topics.
- **Connector:** Restart / Pause / Resume / Stop (single or bulk marked connectors), view offsets, reset offsets, import unsynchronized connectors.
- **ConsumerGroup:** Reset offsets (`TO_EARLIEST`, `TO_LATEST`, `TO_DATETIME`, `TO_OFFSET`, `SHIFT_BY` — all with partition/offset dry-run preview), delete consumer group.
- **Schema:** Set compatibility (`BACKWARD`, `BACKWARD_TRANSITIVE`, `FORWARD`, `FORWARD_TRANSITIVE`, `FULL`, `FULL_TRANSITIVE`, `NONE`) or reset to `GLOBAL`.
- **ConnectCluster:** Encrypt secrets via Vault (`POST .../connect-clusters/{cc}/vaults`), jump to connectors.
- **Namespace:** Switch active namespace, reset Kafka user password (displayed once in a modal popup, never written to logs).

## Configuration

`domite` works out of the box with `~/.kafkactl/config.yml` (or `$KAFKACTL_CONFIG`).

Optional UI preferences, per-context overrides, and custom JSON-Pointer table views can be placed in `~/.config/domite/config.toml` (or `$DOMITE_CONFIG`):

```toml
poll_interval_secs = 5
min_server_version = "1.20.0"

[skin]
name = "catppuccin-mocha"
background = false

[ skin.colors ]
# Optional per-swatch hex overrides
# lavender = "#b4befe"

[contexts.oom-prod]
readonly = true
skin = "catppuccin-latte"

[views.topics]
replace = false
sort = "NAME"
sort_desc = false
columns = [
  { name = "MIN-ISR", path = "/spec/configs/min.insync.replicas", kind = "number", wide = false },
]
```

Structured application logs (with automatic redaction of JWTs, GitLab tokens, passwords, and AES keys) can be enabled by setting `DOMITE_LOG=1` (written to `~/.local/state/domite/domite.log`).
